Nutzer-Entscheidungen: Aufzählungswerte ohne eigenen Wert ab 0. Aufruf ohne `neu` nur für Fehlerklassen.

## B) Aufzählungstypen
- Syntax: `aufzaehlung Farbe { rot, gruen, blau }`, `aufzählung Status {\n offen = 1,\n fertig = 2,\n}`. Komma Pflicht, Umbrüche überall, abschließendes Komma erlaubt. Wert = beliebiger Ausdruck, einmal bei Definition ausgewertet. Ohne Wert: Position ab 0. SyntaxFehler: Mischung mit/ohne Wert, leer, doppelter Name.
- lexer.py SCHLUESSELWOERTER `aufzaehlung`/`aufzählung` → `TokenTyp.AUFZAEHLUNG`; ast_knoten `AufzaehlungsDefinition(name, mitglieder=[(name, ausdruck|None)])`; parser `_anweisung`-Zweig + `_aufzaehlung_definition()`.
- interpreter: `DeutschAufzaehlung(name, mitglieder: dict)` mit `__iter__` (Definitionsreihenfolge), `__repr__`; `AufzaehlungsWert(aufzaehlung, name, wert)` mit `__str__`/`__repr__` → „Farbe.rot"; Gleichheit/Hash = Identität. `_besuche_AufzaehlungsDefinition` → `u.setze`.
- Geht ohne weiteren Code: drucke/Verkettung (`_zu_text`), `für f in Farbe`, `in`, `passe … fall Farbe.rot`, Schlüssel/Mengen; Unveränderlichkeit über `_ziel_setzen` (prüfen).
- Ergänzen: `_hole_attribut` (Aufzählung → Mitglied, sonst AttributFehler „Aufzählung 'Farbe' hat kein Mitglied 'x'"; Mitglied → `name`/`wert`), `_typname` (Mitglied → „Farbe", Aufzählung → „Aufzaehlung(Farbe)"), `_typ_klasse`/`_pruefe_typ` (Typ-Hinweis `sei f: Farbe`, Parameter, Rückgabe, `m.Farbe`).
- Auch: linter.py `_gebunden` bindet den Namen; editor/vscode/syntaxes/deutsch.tmLanguage.json Schlüsselwort (test_editor prüft).
- Festgelegt: `Status.offen == 1` falsch (über `.wert` vergleichen); `<` zwischen Mitgliedern TypFehler; gleiche Werte → verschiedene Mitglieder; Aufzählung neu bindbar wie Klassen; Mitglied `name`/`wert` erlaubt.
- Bruch: `aufzaehlung` als Bezeichner in Fremdprogrammen → CHANGELOG-Hinweis. Builtin `aufzaehlen` unberührt.
- Tests: beide Schreibweisen, mehrzeilig, Komma am Ende; drucke → „Farbe.rot"; name/wert, 0..n; ==/!= auch zwischen Aufzählungen; für-Reihenfolge; passe/fall; Typ-Hinweis ok/TypFehler; `typ(Farbe.rot) == "Farbe"`; Zuweisung an Mitglied/Wert/neues Mitglied TypFehler; unbekanntes Mitglied AttributFehler; SyntaxFehler leer/doppelt/gemischt; `lade … als m` → `m.Farbe.rot`; Linter ohne Fehlwarnung.

## A) Eigene Fehlerklassen
- Syntax: `klasse MeinFehler(WertFehler) { funktion __init__(dies, text, code) { dies.nachricht = text; dies.code = code } }` · `werfe neu MeinFehler("kaputt", 3)` · `werfe WertFehler("Text")` · `fange (MeinFehler, m.AndererFehler) f { drucke(f.nachricht, f.art, f.zeile, f.datei, f.code) }` · `ist_instanz(f, WertFehler)`.
- Fehlerarten als Klassen: `_eingebaute_laden` legt je FEHLERARTEN-Eintrag `DeutschKlasse(name, eltern=[Fehler])` mit Feld `python_fehler` an (`Fehler` → Exception, ohne Eltern). Helfer `_python_fehler(klasse)`: erstes `python_fehler` in der Elternkette (Tiefensuche wie `suche_methode`).
- Instanziieren: Kern von `_besuche_NeuInstanz` → `_instanziieren(klasse, args, kwargs)`; bei Fehlerklassen vor `__init__` `attribute['nachricht'] = _zu_text(args[0]) if args else ''`. `_aufrufen` instanziiert eine DeutschKlasse ohne `neu` NUR für Fehlerklassen; sonst TypFehler „nutze 'neu'".
- Werfen (`_besuche_WerfeAnweisung`): DeutschInstanz → `_ausnahme_klasse(py)(wert)`; `_ausnahme_klasse` cacht `type(..., (AusnahmeFehler, py), {})`, ohne py `AusnahmeFehler`. So greifen `fange (WertFehler)` und `(ValueError)` per isinstance. (Geprüft: für alle 16 FEHLERARTEN baubar, inkl. OSError/KeyError.)
- Erneutes `werfe f`: `Umgebung.gefangen` speichert das Ausnahme-Objekt `e`; `werfe f` → `raise e` (Art, Meldung, Ort, Aufrufkette bleiben; auch `werfe 42`).
- Text/Kopf: `AusnahmeFehler.__str__` gibt bei Instanz-Wert ohne eigene Meldung `nachricht` der Instanz; `fehlerart_name` bei Instanz-Wert → `wert.klasse.name` → CLI `[MeinFehler] Zeile n: Text`.
- `_besuche_anweisung`: im AusnahmeFehler-Zweig `type(e)(e.wert, nachricht=…)` statt `AusnahmeFehler(...)`; `except SyntaxError: raise` nur für Nicht-AusnahmeFehler; `neu.kern = _meldung_deutsch(e)` mitspeichern; `_meldung_deutsch` gibt für AusnahmeFehler sofort `str(e)` zurück.
- Fangen: `_fehlertyp_passt(e, typen, u)` als Methode mit Scope; FEHLERARTEN- und englische Namen wie heute; sonst `_typ_klasse(name, u)` → DeutschKlasse passt, wenn `e.wert` DeutschInstanz und `_ist_instanz_von`; jede Klasse fangbar; unbekannt → NamensFehler mit Vorschlag wie heute. Parser `fange (...)`: `_punktpfad_lesen()` statt BEZEICHNER.
- Gestalt von `f`: a) Python-Fehler und `werfe "Text"` → `DeutschFehler(str)` (Text wie heute; Attribute `nachricht`, `art`, `zeile`, `datei` (nichts = Hauptskript), `_ausnahme`) — bricht nichts: drucke, +, ==, laenge, Zeichenkettenmethoden, `typ(f) == "Zeichenkette"`. b) geworfene Instanz → die Instanz, beim Fangen `art`/`zeile`/`datei` in `attribute` (reserviert, überschreiben Nutzerfelder). c) andere Werte (42, Liste) → roh wie heute.
- `_hole_attribut`: DeutschFehler vor dem str-Zweig (nachricht/art/zeile/datei, sonst Zeichenkettenmethoden). `_zu_text`: Fehlerinstanz ohne `__text__` → `nachricht`. Builtin `ist_instanz(wert, klasse)`: DeutschKlasse → `_ist_instanz_von`; DeutschFehler + Fehlerklasse → `isinstance(f._ausnahme, py)`; Aufzählung → Mitgliedsprüfung; sonst TypFehler. Zwei Fehler-Eltern → erste gewinnt.
